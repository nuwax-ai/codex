# Spec：用户配置直接保存多 Provider API Key

状态：待开发。2026-11-05 用户明确选择本方案，替代此前的独立凭据库/钥匙串方案。
基线：test@dc2fdbd5b4；实施前复核当前 HEAD，保留其他人的改动。
入口：[Claude Code 交接](claude-code-prompt.md)；配套：[Plan](plan.md)、[Tasks](tasks.md)。

## 目标与用户决定

用户希望先正常使用多 provider：在 /model 的管理厂商向导直接粘贴 API key，
保存到用户级配置后即可选用，重启后仍然可用，不强制要求环境变量。

允许 key 以明文保存在运行后端的用户级 config.toml 中；配置文件随备份会携带 key。
默认路径是 ~/.nuwax-harness/config.toml，显式 NUWAX_HOME/CODEX_HOME 和 profile-v2
继续遵守现有文件定位规则。不得将真实 key 写进仓库、示例、测试或项目级 .codex。

AGENTS.md 中“API key 只走环境变量”与本次用户选择冲突；本次用户指令优先。
实施时将约定改为“允许用户级 api_key 或环境变量引用；真实 key 不得提交仓库”，
无需重新向用户询问是否允许按此方案开发。

## 配置合同（以下为拟新增字段）

```toml
[model_providers.my-provider]
name = "My provider"
base_url = "https://gateway.example.invalid/v1"
wire_api = "chat"
models = ["<实际模型 ID>"]
api_key = "<仅示例占位，真实密钥由用户在 TUI 输入>"
```

- api_key：非空、去除输入首尾空白后保存；不改中间内容，不限制前缀/大小写。
- 旧 env_key 模式继续支持，缺变量时保持原先明确报错语义。
- 新 api_key 不允许同时配置 env_key、experimental_bearer_token 或另一种主鉴权。
  冲突加载即报错，只报字段名，不回显值。不以优先级偷偷选其中一把。
- 不扩大对旧配置的冲突拒绝范围；已有 env_key/旧 bearer 行为除安全脱敏外保持兼容。
- 保留 gateway_oauth 等现有二级鉴权组合，不能把所有 OAuth 都当成冲突的主鉴权。
- 本轮面向自定义 provider；官方登录、保留云 provider 的行为不改。
- 本地免鉴权网关可显式选择“无鉴权”；空 api_key 不能被当成无鉴权。

## TUI 行为

凭据方式：直接输入 API Key（默认） / 环境变量（高级） / 无鉴权。
直接输入使用独立隐藏输入框，不能沿用会回显完整 key 的普通文本框。

新增 provider 的步骤：预设或自定义 → 连接信息 → 凭据方式 → 模型 → 脱敏预览 → 保存。
普通配置项仍沿用既有 P4 流程；更改密钥不要求重走全部步骤。

编辑已有 provider 必须区分三个意图：
- 保留：不回填完整旧 key，不提交占位符，也不删除旧 key。
- 替换：用户明确输入新 key 后替换；预览只显示“将更新密钥”。
- 移除/切换来源：明确删除旧来源字段，不是仅在新请求里省略它。

切换来源时，在同一次原子配置写入内删除该用户层旧的互斥来源。
保留该 provider 的其它设置，如 headers、prompt caching、effort 档位、输出上限。
若旧来源属于托管/只读层，无法合法移除，应明确报配置冲突而非绕过策略。

## 生效、列表与轮次边界

- 新增 provider 后，当前 /model 立即刷新并可选，无须 export 或重启。
- 重启、exec 和 ACP 调用同一后端配置时均可使用 api_key。
- 修改当前 provider 的 key，空闲时重新加载鉴权；执行中保留当前轮快照，
  下一轮使用最新 key。不得让“配置已保存”冒充“运行时已应用”。
- 模型切换保留既有规则：执行中多次选择只保留最后一次；收到正常完成或停止
  完成后才切换；后续排队输入不能提前发到旧路由/旧鉴权配置。
- 列表不能继续只检查 TUI 进程环境；状态与实际执行后端的鉴权来源一致。
- 未配置凭据：显示具体原因，并提供 Enter 进入配置的动作，不直接发送模型请求。
- 已配置只表示凭据来源可解析，不保证 key 有效、额度充足或网关支持该模型。

## 密钥保存与脱敏

允许明文存在的范围：用户级配置文件、必要的受限写入请求、程序内部鉴权快照、
发送到目标 provider 的实际鉴权头。配置写入为受限权限与原子替换。

不得自动带入：TOML 预览、config/read 等公开返回、Debug/tracing/原始 JSON
日志、解析错误摘录、doctor、反馈/诊断导出、rollout、模型提示词、测试快照。
不提供“查询完整 key”接口；仅提供 configured/source 等状态。
不承诺阻止拥有用户文件权限的程序或用户主动读取该明文配置。

保存失败时原文件、原 key 和原会话保持可用。取消输入不落盘。
并发写使用现有锁/版本检查，不覆盖其它修改；原子写临时文件与备份同样要受限。

## 第一阶段边界

完成本机 TUI、内嵌 app-server、可信同用户 daemon、exec 和同后端 ACP。
不新增钥匙串、credential_ref、独立凭据库、自动 shell 修改或 set_var 注入。
不自动搬迁现有真实 key，不自动上传本机 key 到远程主机，不改套餐地址或模型名。
远程/旧后端未具备新能力时说明限制；不能悄悄当作免鉴权或转为另一凭据来源。
