# 同一会话切换到小窗口模型的实施方案

审查基线为 `885ebc09c1`。实施前核对当前 HEAD 和已有改动。入口见 [FORK.md §5.3](../FORK.md#53-迁移压缩大窗口会话降级到小窗口模型v01830-起) 和 [NUWAX-HARNESS.md](../NUWAX-HARNESS.md)。

## Spec · 行为合同

同一会话从大窗口切到小窗口，例如从 1M 切到 32K，可以省略部分较早上下文。目标模型可用且必要请求内容能装入窗口时，用户应能在同一会话继续对话。切换沿用现有轮次边界，从切换生效后的首个 turn 开始处理窗口迁移。

| 场景 | 预期 |
|---|---|
| 历史已入目标预算 | 正常推理 |
| 分段摘要在上限内收敛 | 使用摘要和保留尾部继续推理 |
| pass 触顶、摘要不缩减、无合法切点或摘要失败 | 尝试裁剪较早上下文，使用目标模型继续本轮 |
| 仅必要指令、必要工具、当前输入和生成预留就超过窗口 | 保留本轮输入，给出明确超窗错误和可采取的操作 |
| 目标推理服务不可用 | 传播实际错误 |
| 用户主动停止 | 停止后续摘要和推理，已提交的迁移记录仍可回放 |
| 窗口未知，或未发生窗口缩小 | 维持各自现有行为 |

降级时原始会话记录继续保留。裁剪作用于模型可见历史，且恢复会话后边界一致。完整保留当前输入。尽量保留最近的连续历史，旧摘要可在预算允许时保留。调用与结果一起保留或一起裁剪。实际省略较早内容时，本轮提示一次，例如“已切换到较小上下文窗口，部分较早内容已省略”。

## Plan · 实现路径

### 1. 识别迁移并区分处理结果

核对 `codex-rs/core/src/session/turn.rs::run_turn`、`core/src/compact.rs::run_migration_compact_task` 和 provider 切换后的恢复路径。用已有的有效窗口和会话状态识别 downshift，验证跨 provider 恢复后仍能拿到所需的状态。同 slug 换 provider 也可能缩窗，模型名称比较不足以判定。

将 `Result<bool>` 拆成明确结果，区分跳过、已收敛、缩减后仍超预算，以及无法继续摘要。取消作为独立出口。每 pass 结束重算，最后一个允许的 pass 刚好收敛时正常推理。以历史实际缩减判断进展，避免反复写入等长或更长的摘要。保留每 pass 的 `migration_compact_max_ranges` 和每轮 32-pass 上限。

### 2. 给降级路径单独做请求预算

迁移摘要继续采用有界分段和 2048 输出上限。降级推理按目标模型及 provider 的实际请求形态估算，至少计入指令、工具、当前输入、上下文重注入和生成预留。复用已有的请求估算和工具配对规则。估算历史时避免把上一模型总用量或某段摘要的用量直接视为当前请求的前缀成本。

从可保留的最近连续尾部寻找安全边界，按预算向前裁剪旧内容。当前输入和必要前缀优先于历史。明确处理历史尾部完全放不下的情况，允许使用必要前缀和当前输入继续。如果网关实际 tokenizer 仍拒绝估算内请求，仅在可以进一步裁剪、且尚未产生回复或工具副作用时允许有界重试。

确保已识别的缩窗降级使用目标 provider 和模型。检查 `run_pre_sampling_compact` 中旧模型摘要入口，以及采样后的溢出恢复入口，避免把本次未收敛的历史重新交给旧模型或旧全量 trim 路径。普通会话的常规压缩逻辑继续沿用现有规则。

### 3. 让持久化和内存投影一致

从现有 `SurfaceReplacement` 与 `rollout_reconstruction` 入手。摘要、无摘要裁剪和空历史尾部应有明确的持久化语义。核对现有结构是否能表达无摘要裁剪及空尾部，缺少表达时做最小兼容扩展。用稳定的条目标识，确保记录可重放后再安装内存投影。复用有效 checkpoint 的优先级，验证 resume、fork 和 rollback。旧 rollout 仍应正常加载。摘要失败或取消时，本轮输入沿用已有记录规则，验证只落一次。

### 4. 修复零保留比例

修改 `core/src/session/compaction_region.rs::select_compaction_region`。当 `retain_ratio = 0` 且候选 `end == items.len()`，从最后一个实际条目开始向前找。切点仍须带稳定 ID，工具配对闭合，且被替换区间非空。

## Task · 验收顺序

1. **先复现。** 增加两个带 ID 的普通条目测试，零保留且 span 足够时应在第二条之前切开。构建同一会话大窗到小窗的回归，强制达到迁移上限并断言旧压缩路径没有收到请求。
2. **验证降级成功。** 使用本机 32K mock，分别覆盖触顶和只拒绝摘要的场景。断言最终请求走目标模型和 provider，包含当前提问和可保留的近期事实，且同一轮返回回复。触顶 fixture 可以使用较小的测试上限，保留一条完整生产入口的跨 provider 切换验证。
3. **验证可回放和边界。** 对比降级前后的原始记录和重载后的模型可见历史。覆盖旧 checkpoint、取消、工具配对、最小请求仍超窗、空尾部、当前输入只落一次，以及最后一个 pass 恰好收敛。
4. **保留正常路径验证。** 完整 `run_turn` 的正常收敛测试继续检查被移除的测试片段进入过成功摘要，并断言零网关拒绝。800K → 32K、切点及回放测试继续通过。允许损耗的降级测试单独断言裁剪与提示。
5. **同步文档。** 更新 `FORK.md` §5.3，说明摘要、降级、失败和提示，写清模型可见历史与原始记录的区别。将“请求永远装得下”改为预算估算及真实网关限制。更新 `NUWAX-HARNESS.md` 中 `max_ranges` 的每 pass 语义。
