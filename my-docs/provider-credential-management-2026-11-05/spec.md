# Spec：厂商 API Key 直接配置与凭据管理

> 请以 [新方案](../direct-provider-api-key-2026-11-05/claude-code-prompt.md) 为准；本文件仅保留历史分析，不再作为开发要求。

状态：分析建议，尚未实施。源码基线：test@dc2fdbd5b4（2026-11-05）。
配套：[Plan](plan.md)、[Tasks](tasks.md)。

## 问题

现有 P4 向导只保存 env_key 名称。用户自然会把实际密钥粘进“API key”步骤，
结果触发变量名校验；保存 provider 后仍需理解 Shell、环境继承和重启。
/model 还在 TUI 进程内检查 std::env::var，与实际执行模型的后端可能不一致。

目标：普通用户在 TUI 直接输入 key，保存后即可选模型；重启后继续可用。
密钥不进入普通配置、项目文件、会话历史、提示词、诊断导出和日志。

## 用户行为

新增厂商：选择预设/自定义 → 连接信息 → 凭据方式 → 模型 → 预览 → 保存。

凭据方式：
- 直接输入 API Key（默认）：专用隐藏输入框，保存到独立凭据存储。
- 引用环境变量（高级）：保留现有 env_key，用明确的“环境变量名称”文案。
- 无鉴权：显式选择，适用于免鉴权网关；不以空 key 冒充保存成功。

默认优先使用系统钥匙串。系统不支持钥匙串时，提供显式的“本机凭据文件”
选项，注明保存位置和明文属性；不能在钥匙串故障/拒绝访问时静默写文件。
本机文件使用受限目录、0600 权限及原子写入；Windows 使用相应用户 ACL。
禁止把实际 key 写入 config.toml、shell rc 或项目环境文件。

已配置厂商提供：补充/替换密钥、删除密钥、切换凭据方式、测试连接。
编辑时只显示“已保存”，不把完整旧 key 回填输入框。

## 模型列表

凭据状态由实际运行模型的 app-server/引擎提供，不由 TUI 自行读取本机环境。
普通灰色说明文字仍只是视觉样式；缺少凭据需要可理解且可修复的状态：

| 状态 | 展示与操作 |
|---|---|
| 凭据可读取 | 正常选择；不宣称网络/额度/模型能力已验证 |
| 尚未配置 | 显示“未配置密钥”，Enter 进入配置，不发起模型切换 |
| 已保存但暂不可访问 | 显示“凭据暂不可访问”，重试/管理；不当成未配置而覆盖 |
| 后端不支持管理 | 说明限制，保留环境变量配置路径 |

“保存成功”和“连接测试通过”分别呈现。测试连接使用所选协议和模型的最小
推理请求，设置明确时限；不能用通用 GET /models 的 404 判定密钥失效。

## 生效边界与兼容

- 保存后当前后端立即可解析凭据，无须重启或重建系统环境变量。
- 正在执行的轮次保留原模型/凭据快照；下一轮取得最新配置与凭据。
- 模型切换继续遵守已确认的规则：执行中只保留最后一次选择，正常结束或停止
  完成后切换；未应用新路由前不自动发送后续队列。
- 旧 env_key 配置保持原语义。选定的凭据来源缺失即报错，不偷偷换另一来源。
- 多个互斥的主凭据来源同时配置时 fail-fast，不引入隐含优先级。
- OpenAI 登录、命令鉴权、网关 OAuth、云平台凭据不在本轮重构范围。

## 范围与所有权

凭据由运行推理的后端持有，按用户目录身份、凭据 id、provider 和端点绑定隔离。
同名 provider、不同 NUWAX_HOME 不共用密钥；修改目标端点不能无确认地继承旧 key。
多个协议入口可由用户明确复用凭据，第一期不自动按域名共享或猜测厂商归属。

第一期完成本机 TUI、内嵌 app-server、可信本机 daemon 和 exec 共用解析。
ACP 调用同一后端时复用该能力，不另存一份密钥。
远程后端的凭据属于远程主机：第一期只查询能力/状态，不自动把本机 key 同步
过去，不向任意 WebSocket 连接开放写凭据功能。

## 非目标

不修改系统全局环境变量，不在多线程 Rust 进程中调用 set_var 注入 key；
不以 experimental_bearer_token 明文配置替代凭据库；不自动迁移所有旧 key；
不做跨机器密钥同步、费用查询或完整账号管理。

实施时需要同步修订 AGENTS.md 的“API key 只走环境变量”约定、FORK.md §7.5
和 NUWAX-HARNESS.md：允许环境引用与独立凭据引用，仍禁止提交真实 key。
