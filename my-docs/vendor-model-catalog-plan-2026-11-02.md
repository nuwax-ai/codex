## 1. 背景与目标

nuwax-harness 是多厂商 harness,三方模型(GLM/MiMo/Step/DeepSeek/Ollama 等)是
默认使用场景。但引擎对模型目录之外的模型走 fallback 分支,只有占位元数据,
导致三方模型在十余个功能点上与官方目录模型行为不一致(§2)。

**本需求的目标**:

1. 让主流三方模型获得与官方目录模型同级的元数据待遇,消除因"无元数据"产生的
   功能差异;
2. 确立"用户显式配置优先于目录"的上下文窗口语义,支持可配置窗口模型
   (如阿里云 qwen 系可在服务端调整上下文宽度);
3. 修正两处与现有决策不一致、且不依赖目录的行为(§6)。

**设计总原则**:fork 的正确姿势不是"删掉官方目录的特权",而是"给厂商模型
同等的元数据待遇"——修一致性、补数据、不装懂。

## 2. 现状:fallback 与官方目录模型的全部功能差异(14 项)

引擎按 slug 查模型目录,未命中则生成占位元数据(fallback,`model_info_from_slug`),
并以 `used_fallback_model_metadata` 标志驱动全库 11 处分支。逐项核对
(2026-11-02,代码行为以当日 test 分支为准):

| # | 功能点 | 官方目录模型的行为 | 三方模型(fallback)的现状 | 对用户的实际影响 |
|---|---|---|---|---|
| 1 | 系统指令 | 家族专属 prompt(gpt-\* 仍为上游 Codex 身份) | fork 中性模板,身份行渲染实际 slug | 无(已是正确行为) |
| 2 | 上下文窗口 | 目录真实值 | 占位 272k,静默生效 | GLM(1M)被砍半预算;压缩阈值跟着错;用户无感知 |
| 3 | 显式窗口覆盖 | 被目录上限钳制 | 全额生效(fork 2026-10-28 已改) | 可配置窗口模型(目录 131K、云端开 1M)无法用满 |
| 4 | 自动压缩阈值 | 目录显式值 | 按窗口 90% 派生 | 窗口正确后自动正确 |
| 5 | 有效窗口百分比 | 按模型配置 | 固定 95% | 小差异 |
| 6 | 推理档位(effort) | 有预设列表与默认档,UI 可选、按档校验 | 空:无预设、无默认、不校验 | 选了模型不支持的档位只能靠网关静默降档(正是 effort 档位门修过的坑) |
| 7 | guardian 审阅预算 | 按模型窗口 | 钳到 128k,**显式配置也被钳** | 审阅/复核线程预算与主会话窗口不一致 |
| 8 | 模型切换 | 轮内转向允许 | 轮内转向被拒(轮间切换不受限,已实测可用) | 轮内换模型不可用 |
| 9 | 子 agent effort 校验 | 按目录预设校验 | 跳过 | 传错档位不拦截 |
| 10 | 审阅模型档位映射 | 不支持时映射到中位档 | 跳过,沿用父会话档位 | 小 |
| 11 | 审阅线程图片准入 | 按模态声明准入 | 一律不认 | 多模态模型做审阅时带不了截图 |
| 12 | Code Mode 警告 | 未声明支持会告警 | 静默 | 无(不误报是正确行为) |
| 13 | 工具面 | 按模型声明 | search tool 不开、web_search 固定 Text、输出截断 bytes(10k)、UnifiedExec | search tool 缺失 |
| 14 | 模型列表可见性 | 展示 | 隐藏 | 无 |

**差异根因分类**:除 #1/#4/#12/#14 外,其余全部源于"没有厂商元数据"。
因此处置策略分三类:

- **A 类(直接修,不依赖目录)**:#7 预算钳制与既有决策矛盾、#2 的静默占位
  违反 fail-fast —— 见 §6;
- **B 类(目录落地后自动消失)**:#2 #3 #5 #6 #8 #9 #10 #11 #13 —— 见 §3-§5;
- **C 类(保持不动)**:#1 #4 #12 #14。

已验证前提(2026-11-02 实测):轮间模型切换(同线往返 + 跨线 anthropic↔chat)
在双 fallback 组合下四轮全过、上下文连续、零告警——切换能力不缺。

## 3. 需求一:厂商模型元数据目录

### 3.1 数据源

- **主数据源:models.dev**(SST/opencode 维护的开源模型数据库,MIT)。选定
  理由(2026-11-02 实测):
  - 覆盖 fork 关心的全部厂商,且粒度到**套餐端点**(存在 `zhipuai-coding-plan`、
    `xiaomi-token-plan-cn`、`alibaba-coding-plan-cn`、`stepfun-step-plan`、
    `minimax-cn-coding-plan` 等条目),与 fork 服务对象一一对应;
  - 数据与实测一致(glm-5.3-flash 窗口 1M = 我们的探针结论);
  - opencode 消费同源,社区持续更新,可回馈纠错;
  - 备选(LiteLLM 价格表/OpenRouter API)为厂商粒度或需运行时联网,不作主源。
- **快照方式**:构建期拉取并打包进发行物,**运行时零网络依赖**(与现有
  fail-fast/可复现构建取向一致);快照允许滞后,由 overlay 热修先行。
- **刷新**:发版流程提供刷新步骤;上游 schema 漂移需可检测(锚点校验)。

### 3.2 数据覆盖范围

纳入快照的厂商(白名单,可增删):智谱(zhipuai/zai 及各 coding-plan)、小米
(xiaomi 及各 token-plan,含 cn/ams/sgp)、阿里(alibaba 及 coding-plan/token-plan)、
阶跃(stepfun 及 step-plan)、DeepSeek、MiniMax(含 coding-plan)、月之暗面
(moonshotai)、SiliconFlow(含 cn)、Ollama Cloud。

### 3.3 解析层级

模型 slug 的元数据按以下顺序解析,命中即止:

```
1. 官方内置目录(gpt-* 等,维持 upstream 不动)
2. nuwax 厂商目录(models.dev 快照 + fork overlay)
3. 用户扩展目录(~/.nuwax-harness/models.d/)
4. fallback(占位元数据 + §6.2 告警)
```

命中第 2/3 层的模型视同目录模型(不再带 fallback 标志),§2 的 B 类差异全部
消失。所有层级之上,用户显式配置(环境变量 / `-c` / config.toml)仍可覆盖
(§4)。

### 3.4 匹配规则

- 同一 slug 可能命中多个厂商条目(如 glm-5.3-flash 同时在 zhipuai、zai、
  两个 coding-plan 条目下):**必须显式消解**(优先套餐类条目;无法消解时
  取窗口最大者并留痕告警,禁止静默任选);
- fork overlay(§3.5)可为模型声明条目别名,彻底消除歧义。

### 3.5 fork overlay(仓库内维护的补充数据)

models.dev **不提供**而 fork 需要的信息,由 overlay 补齐:

1. **推理档位表**(如 GLM-5.3 系:low/high/max)与默认档——fork 探针/厂商
   文档的结论,错误可热修不等上游;
2. **条目别名**(模型 slug → models.dev provider 条目的映射);
3. **有效窗口百分比**的按厂商配置;
4. (展示用)推荐的协议线提示,不参与路由决策。

## 4. 需求二:上下文窗口优先级语义

**用户显式配置优先级最高,双向生效;目录提供默认值与参考上限。**

| 场景 | 期望行为 |
|---|---|
| 目录 1M,用户显式设 200K(限流/省钱;或阿里云在服务端把模型调成 200K) | 按 200K 生效(压缩阈值等随之派生) |
| 目录 131K,但用户在云端把可配置窗口模型开到 1M,显式设 1M | **按 1M 生效,并给启动告警**(点名变量、目录值、实际生效值)——**不得静默钳制** |
| 未显式配置 | 按目录值;无目录命中 → 272k 占位 + §6.2 告警 |
| 非正数 | 加载即报错(现有行为,保持) |

**"向上告警不钳制"的理由**:可配置窗口模型的服务端事实由用户掌握,本地目录
不是部署权威;静默钳制会让合法配置永远用不满,且违背 fail-fast 约定(要么按
用户值、要么大声说出来)。误配风险由告警与 doctor 来源标注兜底。

**可观测性要求**:doctor 的窗口信息必须标注**来源与双侧数值**——
目录来源(provider 条目与数值)、显式覆盖(变量名与数值)、占位(标明
placeholder);显式值高于目录上限的组合要能一眼看出。

## 5. 需求三:effort 档位的目录化

1. 目录(overlay)可为模型声明档位表与默认档;声明后,选了表外档位在
   **发送前**被拒并给出可用档位——语义与现有 provider 级
   `reasoning_effort_levels` 完全一致,目录只是把它变成默认值;
2. **覆盖关系**:provider 显式配置 > 用户扩展目录 > overlay;
3. **逃生口**(目录档位错误时无需发版即可绕开):提供按 provider 关闭目录
   档位、回退宽松行为的显式配置;不得复用"空列表"(现有语义中空列表 = 配置
   错误,保持不变);
4. 只有 models.dev 的 reasoning 布尔、没有 overlay 档位表的模型:**不发明
   档位**,维持无预设现状(不装懂原则)。

## 6. 需求四:A 类修正(不依赖目录,先行)

### 6.1 guardian 审阅预算与窗口信任对齐(差异 #7)

现状:审阅预算对 fallback 模型钳到 128k,**即使用户已显式配置真实窗口**——
这与 2026-10-28"显式窗口是三方模型最好信息、全额生效"的既有决策自相矛盾。

要求:钳制**仅在"无目录元数据且无显式窗口配置"**时生效;显式配置了窗口的
模型(无论 fallback 与否)按配置值计算审阅预算。

### 6.2 fallback 占位窗口启动告警(差异 #2 的未收录部分)

现状:按 272k 占位预算只有调试级日志,用户无感,违反"不静默取默认值"约定。

要求:走 fallback 且未显式配置窗口时,启动时给**告警**,内容必须点名:模型
slug、占位值 272k、应设置的配置项名;同一模型重复解析不重复告警。

## 7. 需求五:用户扩展目录 models.d

- 位置:`~/.nuwax-harness/models.d/*.toml`(与 NUWAX_HOME 联动);
- 用途:目录未收录的私有网关/新模型,用户自行提供元数据(窗口、档位表、
  百分比等,字段同 overlay);
- 校验:格式错误**加载即报错并点名文件与字段**,不静默跳过(fail-fast);
- 优先级:高于内置 overlay、低于 provider 显式配置;
- 文档:使用方法进 NUWAX-HARNESS.md 与 usage-guide。

## 8. 非功能需求与约束

1. **零运行时网络依赖**:目录数据构建期打包;无网环境构建与运行均正常;
2. **fail-fast**:所有配置层(显式/models.d/overlay)的非法值报错点名来源,
   不静默取默认;
3. **体积**:打包快照 ≤200KB(仅白名单厂商子集;2026-11-02 用户决策由 150KB 放宽——保留 models.dev 原始字段、转换脚本从简,不裁剪 description 等长文本;实测白名单子集 173KB);
4. **向后兼容**:现有一切配置行为不变——不配任何新东西的用户,行为至多是
   "多了目录默认值与告警",无破坏;
5. **upstream 合并面**:数据文件放 upstream 不存在的路径(零冲突);对上游
   文件的修改点收敛并记入 FORK.md;不采用 upstream 的运行时联网拉目录链路;
6. **Ollama 本地模型**:窗口取决于本地部署,目录值仅作默认,显式覆盖优先
   (§4 语义天然覆盖);
7. 数据许可:models.dev 为 MIT,快照带来源与生成时间标注。

## 9. 验收标准

1. GLM/MiMo 套餐 e2e **零配置**:doctor 显示目录来源的真实窗口(1M),溢出
   压缩行为与显式配置一致;
2. 显式向下覆盖(1M→200K)生效,doctor 标注来源;
3. 显式向上覆盖(目录 131K→用户 1M)生效且出现启动告警,doctor 双侧标注;
4. 零配置下 GLM-5.3-Flash 选 `medium` 在发送前被拒(目录档位门默认生效);
   provider 显式配置可覆盖;逃生口可回退宽松;
5. 目录命中模型:轮内转向不再被拒、审阅预算按模型窗口、审阅线程图片按模态
   准入、search tool 按 tool_call 能力开放;
6. §6 两项:显式配置后审阅预算不再被钳;fallback 未配置出现点名告警且不重复;
7. models.d:目录外模型可扩展生效;坏文件报错点名;
8. 快照:刷新脚本幂等、体积上限生效、锚点数据漂移可检测(测试红);
9. 全量回归基线通过(fmt/clippy/nextest)。

## 10. 非目标

- 轮内转向(step_activation)守卫的放开——目录落地后自然解锁,不单独修改;
- 运行时联网拉取目录;
- cost 字段的用量计费功能(数据已备,另立项);
- §2 中 C 类四项(系统指令中性模板、压缩阈值派生、Code Mode 静默、可见性)
  ——保持现状;
- 官方目录(gpt-\*)的任何削弱。

## 11. 决策记录(2026-11-02 用户拍板,社区调研对照后)

调研对照:opencode(models.dev 主要消费者)——构建期快照内置 + 默认开启的
运行时刷新;同 ID 用户模型条目为"克隆目录条目后逐字段覆盖"
(`mergeOverlay` 递归深合并,未设字段保留目录值);选择器只显示已配置/
已连接 provider 的模型。fork 的"零运行时网络"为企业需求的刻意偏离。

1. **models.d 覆盖粒度:逐字段深合并**(与社区先例及本 Spec 倾向一致);
2. **档位表初始覆盖面:仅实证过的先上**(首批只有 GLM-5.3 系实证 low/high/max;
   其余厂商无档位表 = 维持宽松现状,逃生口纠错;不按厂商文档抄录未实证数据);
3. **模型列表可见性:维持隐藏**(目录只影响元数据行为,不改 TUI 列表;
   后续可按需放开);
4. **快照体积:放宽到 200KB**(见 §8.3)。
